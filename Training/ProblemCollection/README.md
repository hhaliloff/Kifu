# Исходные задачи го — не готовый сборник с ответами

Здесь находятся 1050 исходных позиций из трёх файлов проекта [tasuki2sgf](https://github.com/Seon82/tasuki2sgf): 520 Gokyo Shumyo, 347 Xuanxuan Qijing (`xxqj`) и 183 Igo Hatsuyoron. В `sources/` сохранены исходные SGF; в `problems/` — отдельный SGF на каждую позицию. `source_manifest.json` связывает каждую позицию с исходным файлом, подписью, стороной хода и SHA-256 источника. `extract_sources.py` воспроизводит разбиение.

**Ни один ответ не подтверждён.** Значение `validation: pending` и `solution: null` намеренное. Эти файлы нельзя импортировать в приложение как проверенный учебный сборник.

## Что требуется для проверки

1. Для каждой задачи определить цель (жить, убить, ко, сэмэай, соединение и т. п.), ключевую группу и допустимую область. Одна только `PL` и расстановка из SGF не задают критерий правильности ответа.
2. Для применимых задач запустить [study-LD-RZ](https://github.com/rlglab/study-LD-RZ) с корректным JSON-описанием. Его формат содержит `winning_color`, `*_crucial_stone`, `*_search_goal`, правила ко и область поиска. Репозиторий описывает себя как решатель задач на жизнь и смерть; для остальных типов задач применимость нужно установить отдельно.
3. Запустить KataGo с моделью, достаточным бюджетом поиска и **той же целью локальной задачи**. Лучший ход в обычном анализе всей доски не равен обязательно решению задачи на жизнь и смерть.
4. Сохранять задачу в итоговый сборник только при совпадении проверенных решений и после проверки ответных ходов/вариантов. Неуспех запуска или отсутствие решения нельзя считать расхождением движков.
5. До коммерческого распространения отдельно проверить права на исходные SGF. На странице проекта-источника лицензия для этих файлов не указана.

Среда, в которой подготовлен исходный набор, не содержит `podman`/`docker`, `Boost`, `CUDA` и `Caffe2`, необходимых для указанного в README запуска study-LD-RZ. Сам решатель в этой среде не запускался; KataGo для этих задач тоже не запускался.

## Предварительная разметка

`annotate_positions.py` создаёт `position_annotations.json` с типом задачи (по разделам Gokyo Shumyo), связными группами, свободами и кандидатами на целевую группу. Все поля проверки остаются неподтверждёнными. Из 1050 позиций 520 получили тип по разделу источника; 530 не классифицированы. В 174 задачах на жизнь/убийство только 9 имеют единственного кандидата по цвету, поэтому выбор группы нельзя автоматизировать без проверки.

Для просмотра откройте `review.html` в браузере, загрузите `position_annotations.json`, выберите тип и целевую группу и скачайте `review_decisions.json`. Этот файл фиксирует решения разметки, но не ответы задач.
